# Pantry Pulse Proof Checklist

## Runtime Commands

- Install dependencies or verify no install is needed.
- Run automated unit/component checks.
- Build the app or run the smallest equivalent static validation.

## Runtime Server

- Start runtime dev server.
- Record container/runtime state.
- Record host URL or port mapping.

## Design Proof

- Record design foundation evidence.
- Capture desktop and mobile screenshots.
- Verify filter controls use the right persistent-mode control semantics.
- Record palette rationale for product mood, color roles, saturation budget, and contrast.
- Audit actual palette tokens across CSS, Sass/Less, JavaScript/TypeScript, JSON, or the project token source, and reject generic blue primary/accent choices for this domestic food app unless the accepted design packet justifies them.
- Record a design decision packet for accepted feedback.
- Record at least one reusable-vs-local design finding classification.
- Capture design reviewer approval.

## Browser Proof

- Open the app and verify the `Pantry Pulse` title.
- Verify at least five seeded pantry items are visible.
- Browser-proof expiring-soon filter behavior.
- Browser-proof expiring-soon filter and Mark used flow.
- Verify `Mark used` updates the visible count.

## Handoff

- Produce completion handoff with proof path refs.
- Record residual risk and out-of-scope work.
- Record memory proposals for any repeated lesson or workflow miss.
- Verify UI/API/MCP can explain the result without transcript archaeology.
